# Воспроизводимость

## Что можно повторить

| Этап | Включённые входные данные | Статус |
|---|---|---|
| Статистический анализ и графики | `data/processed/matched_pairs.csv` | Полностью запускается; основной эффект и bootstrap CI совпадают с историческими |
| Кандидаты и скоринг | Два обработанных каталога | 53 436 пар; оценки совпали с историческим CSV |
| Кросс-валидация ML | 882 размеченные пары и семь фиксированных признаков | Запускается; сохранены исторические метрики и сравнение повторного запуска |
| Новые ML-предсказания | Результат matching + разметка + выбранный CV-порог | Необязательный воспроизводимый этап; не меняет итоговые пары |
| Очистка исходных каталогов | Две локальные raw-выгрузки + словари + сохранённые ручные решения | Проверено локально; raw не входят в публичную версию |
| Получение ручных решений заново | Карточки/изображения, решения автора | Не автоматизировано; метки и финальный выбор сохранены как входные данные |
| Сбор актуальных каталогов | Доступ к внешним источникам | В репозиторий не входит; новый срез не равен историческому |

**Весь путь от сайта до финальной выборки не является полностью автоматическим.** Повторяемость статистики по сохранённым парам не означает воспроизводимость решений человека без сохранённых меток.

## Окружение

Проверено на Python 3.12.14, Windows. Основные версии закреплены в `requirements.txt`.
`requirements-lock.txt` содержит полный снимок проверенного окружения; это фиксация окружения подготовки портфолио, а не восстановление неизвестных версий исходного исследования.

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

macOS/Linux:

```bash
source .venv/bin/activate
```

После активации:

```bash
python -m pip install -r requirements.txt
python scripts/analyze_prices.py
python scripts/ml_experiments.py
python scripts/validate_project.py
```

Для максимально точного повторения установленного окружения используй `python -m pip install -r requirements-lock.txt`. Полный запуск на macOS/Linux не проверялся; Windows-зависимость `pywinpty` в lock-файле имеет условие платформы.

## Ноутбуки

```bash
python -m jupyterlab
```

Рекомендуемый порядок: 01 → 02 → 03 → 04. Каждый ноутбук самостоятельно загружает входные данные. Для просмотра выводов можно начать с 04.

Для автоматического выполнения всех четырёх с новым ядром для каждого:

```bash
python scripts/run_notebooks.py
python scripts/validate_project.py
```

Скрипт использует тот же интерпретатор Python, которым его запустили. Результаты matching сохраняются в игнорируемую `data/interim/`. Повторный запуск анализа обновляет `reports/`, не меняя входные цены и финальные пары.

## Необязательные этапы

Построить кандидатов без Jupyter:

```bash
python scripts/matching.py
```

Полный прогноз для неразмеченных кандидатов: включи `RUN_FULL_PREDICTION` в ноутбуке 03 после выполнения 02. Эти прогнозы не перезаписывают исторические 841 пару.

Повторить подготовку по двум историческим raw-выгрузкам:

```bash
python scripts/prepare_data.py
```

Имена исходников — в `data/raw/README.md`. Словари и 132 строковых исторических решения берутся из `data/reference/`. Они восстанавливают принятый финальный снимок, а не создают новую разметку. Проверка восьми ключевых полей сохранена в `reports/preparation_validation.json`; исходные обработанные снимки не перезаписываются. Для другой выгрузки нельзя использовать строковые решения без повторной проверки.

## Расхождения и численная точность

- Основной эффект **2,165997%**, отношение **1,02165997**, медиана **1,343284%**, p-value t-теста **0,0000302163**, bootstrap CI **[1,127608%; 3,160069%]** повторяются. В README значения округлены.
- В t-интервале используются квантили t-распределения; его границы **[1,146723%; 3,195543%]** отличаются от bootstrap-интервала. Эти интервалы не смешиваются.
- Обычное среднее процентных различий равно **3,203536%**, а не 2,17%.
- Пересчёт логарифмов из цен может слегка менять совпадения машинных чисел и ранги Wilcoxon на последнем знаке. Статистика Wilcoxon при текущем пересчёте отличается от сохранённого вывода рабочего ноутбука; p-value остаётся значительно ниже 0,05. Не заявляется побитовое совпадение каждого вспомогательного теста.
- При историческом CV-пороге 0,75 Random Forest имел precision **96,22%**, recall **75,92%**. В проверенном повторном запуске общий выбор по правилу precision ≥95% — Logistic Regression, порог **0,70**, precision **95,22%**, recall **77,75%**. Причину различий без зафиксированного исходного окружения установить нельзя; значения не подгонялись.
- Порог подбирается на тех же OOF-предсказаниях, на которых оцениваются метрики; отдельного нетронутого теста нет. Группировка по Sklavenitis не исключает повторение AlphaMega между folds.
- Сохранённые признаки ML уже рассчитаны на полном пуле текстов. CV относится к классификатору на готовых признаках, а не к полностью изолированному обучению текстового представления.

## Что проверяет validate_project.py

Количество и уникальность итоговых пар; положительность цен; соответствие сохранённых разностей и log-ratio исходным ценам; исторический эффект, p-value и bootstrap CI; баланс 882 меток; размеры каталогов; валидность ноутбуков и отсутствие сохранённых ошибок. Если matching уже выполнен, дополнительно проверяются 53 436 кандидатов и все семь признаков на размеченных парах.
